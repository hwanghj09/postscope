# PostScope

Actions가 매일 갱신한 게시 데이터를 보여주는 **정적 웹 대시보드**입니다. JSON 가져오기·Telegram 계정 수집을 위한 로컬 앱도 제공합니다. 메시지 본문·첨부파일을 저장하지 않으며, 외부 AI나 CDN을 호출하지 않습니다. 공식 Telegram 제품이 아닙니다.

## 웹사이트

처음 연결하는 경우 **[실제 Telegram 데이터 연결 가이드](docs/TELEGRAM_SETUP.md)**에서 Windows 설치·인증·첫 수집 실행·오류 해결 절차를 확인하세요.

**https://hwanghj09.github.io/postscope/**

웹은 정적 파일로 제공됩니다. Actions가 매일 **09:05 (Asia/Seoul)** 한 번 데이터를 갱신하고 웹을 배포합니다. 웹에서는 저장된 스냅샷을 표시하며, 로그인·실시간 수집·업로드 서버가 없습니다. 최초 화면은 JSON 집계 파일만 읽고, 추가 필터·내보내기는 브라우저에서 기존 Python 분석 엔진을 실행합니다.

현재 수집 대상은 **유빈 아카이브(https://t.me/yubin_MPGA), 전체 작성자**입니다. 합성 데이터 생성·게시 경로는 꺼져 있습니다. 최초 실제 수집 전에는 통계 대신 연결 대기 상태를 표시합니다. `public/source.json`에 소스 설정을, `public/dataset.json`에 마지막 정상 데이터를 보관합니다. 수집 실패 시 파일을 교체하거나 사이트를 배포하지 않아 마지막 성공 데이터를 유지합니다. GitHub의 예약 실행은 서버 부하에 따라 지연될 수 있습니다.

실제 채널을 연결하려면 본인의 PC에서 GitHub CLI에 로그인한 뒤 다음을 실행하세요. 앱 ID·해시·세션·대상 방을 GitHub Secrets로 직접 저장하며 인증값은 화면이나 Git에 출력하지 않습니다.

```bash
uv sync --frozen
uv run python scripts/configure_daily.py --repo hwanghj09/postscope --chat yubin_MPGA
```

이후 Actions의 **Deploy website → Run workflow → collect 체크**로 수집을 실행합니다. Secrets는 `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`, `TELEGRAM_CHAT`입니다. 현재는 전체 작성자·**2025-08-01(한국 시간)부터 현재까지**를 조회합니다. `public/source.json`의 `start_date`로 시작일을 바꿀 수 있으며 날짜가 지나도 과거 기록을 최근 90일로 잘라내지 않습니다. 게시 본문·파일·원본 계정 ID·세션을 공개 데이터에 넣지 않습니다.

## 실행

Python **3.11 이상**이 필요합니다. 최초 의존성 설치에는 인터넷이 필요하며, 설치 후 JSON 분석과 보고서 열기는 오프라인으로 가능합니다.

**Windows:** `start.bat` 실행. Python 런처 `py` 또는 [uv](https://docs.astral.sh/uv/)가 있어야 합니다.

**Linux / macOS:**

```bash
./start.sh
```

**uv를 직접 사용하는 경우:**

```bash
uv sync --frozen
uv run python -m postscope
```

브라우저에서 **http://127.0.0.1:8765** 를 엽니다. 기본 실행은 이 PC의 루프백 주소에만 바인딩하며 외부 배포나 공개 터널을 만들지 않습니다. 다른 포트·저장 위치는 `./start.sh --port 8766 --data-dir /원하는/경로`로 지정합니다. 실행을 끝내려면 터미널에서 Ctrl+C를 누릅니다.

uv가 없으면 실행 스크립트가 Python 가상환경을 만들고, 해시가 잠긴 `requirements.txt`를 설치합니다. `uv.lock`에는 개발 의존성까지 잠겨 있습니다. GitHub Actions에서 Linux·Windows의 서버·브라우저 테스트를 검증합니다. Windows 실행 스크립트의 직접 실행은 별도 확인 대상입니다.

## 사용

1. 처음에는 **합성 데모 4,284건**을 표시합니다. 실제 대화가 아니며 상단에 DEMO 표시가 나옵니다. 기본 분석 기간의 2,266건은 2026년 10월에 해당합니다.
2. **가져오기**에서 파일을 선택합니다. 데모에서는 가져오기를 확정할 때 실제 데이터용 작업공간을 만듭니다. Telegram Desktop에서 대화를 **JSON**으로 내보내고 파일을 선택합니다. 미디어를 내보낼 필요는 없습니다.
3. 여러 대화가 포함된 파일은 가져올 방을 선택합니다. 전체 파일 구조를 검사하며 최대 100 MiB입니다. 시간대 없는 날짜를 해석하려면 원본 시간대를 지정합니다. 오류 행을 격리하고 정상 행을 가져오는 방식을 명시적으로 확인합니다.
4. 내보내기 기간을 확실히 아는 경우에만 시작·종료일을 확인합니다. 미확인 상태에서는 관측 건수만 분석하고 일평균·요일 평균·정규화 게시율을 제한합니다. 가까운 게시 시각으로 앨범을 추정하지 않으며, 앨범 식별자와 경계 관측 근거가 있어야 묶음 집계를 제공합니다.
5. 방·작성자·날짜·시간대·자료 유형·전달 포함·집계 단위·연속 게시 기준을 선택하고 **적용**를 누릅니다. 변경 중인 조건에는 ‘변경 미적용’이 표시됩니다.
기간의 **최근 7일·30일**은 대화의 마지막 기록을 기준으로 선택합니다. 시간대·집계·전달·연속 기준은 **상세 필터**, 간격·유형·연속 묶음 차트는 **추가 분석**에서 펼칩니다.

6. 날짜 추이, 요일·시간 분포, 히트맵, 게시 간격, 연속 묶음, 자료 유형을 확인합니다. 히트맵은 방향키 탐색·표 전환을 지원합니다. **게시 기록**은 본문 없이 50행씩 표시합니다.
7. **기간 비교**는 현재 분석 기간과 겹치지 않는 기준 기간을 선택합니다. 기준값 0이면 증감률을 계산하지 않습니다.
8. **내보내기**에서 HTML, CSV ZIP, PNG와 CSV를 묶은 ZIP 또는 히트맵 PNG를 저장합니다. HTML에는 차트 스크립트와 한글 글꼴까지 포함됩니다. 실제 계정·대화 ID는 기본으로 가명 처리하며 포함하려면 별도 체크합니다.

검증용 파일은 `tests/fixtures/reference.json`입니다. 원본 시간대 Asia/Seoul, 확인 기간 2026-11-01~03, 분석 날짜 2026-11-02로 설정하면 메시지 3건, 게시 묶음 2개, 게시 간격 중앙값 21,600초가 됩니다. 범위가 미확인이면 경계가 확인되지 않은 앨범은 제외됩니다.

## 텔레그램 API 연결

1. [my.telegram.org](https://my.telegram.org)에서 본인의 API ID와 API Hash를 발급합니다.
2. 가져오기 창의 **텔레그램 API** 탭에서 앱 정보와 국제 형식 전화번호를 입력합니다.
3. Telegram으로 받은 코드와 필요 시 2단계 인증 비밀번호를 **로컬 화면에 직접** 입력합니다.
4. 접근 가능한 방을 불러오고 기간을 설정한 뒤 **표본 점검**을 실행합니다. 표본의 작성자 식별과 앨범 지원 상태를 확인하고 수집합니다.
5. 품질 화면에서 처리 수·커서·일시정지·재개·취소·대기 시각을 확인합니다. 재시작 후에는 원래 계정으로 다시 연결한 다음 작업을 재개합니다. 마지막 페이지를 겹쳐 읽고 중복을 제거합니다.
6. 새 기록을 갱신하려면 마지막 수집일보다 **7일 앞선 날짜부터 새 작업**을 실행합니다. 같은 메시지는 기본 키로 병합합니다. 과거 수집 작업과 갱신 작업의 커서를 섞지 않습니다.

SDK는 메모리 세션만 사용합니다. 평문 `.session` 파일이나 로그인 비밀값을 분석 DB·보고서에 넣지 않습니다. 재시작하면 재인증이 필요합니다. 한 계정의 수집 worker는 하나이며 호출 제한은 계정 전체에 적용해 SQLite에 대기 시각을 보관합니다. 앱을 다시 시작하거나 새 작업을 만들어도 대기를 건너뛰지 않습니다.

연결 중 관측한 기존 메시지 수정과 방을 특정할 수 있는 채널 삭제 업데이트를 반영합니다. 비채널 삭제처럼 방을 알 수 없는 이벤트는 추정해서 삭제하지 않습니다. 앱 종료 중의 수정·삭제를 전부 복구한다고 보장하지 않습니다. 설정의 연결 해제는 로컬 삭제와 원격 세션 해제 성공 여부를 구분합니다.

**실제 계정/API 인수검사는 미실행입니다.** 제공된 계정·방이 없어 로그인·수집·수정·삭제의 실서비스 동작은 확인하지 않았습니다. 합성·모의 API 테스트 통과는 실제 방의 기록 확보나 Telegram 접근 권한을 보증하지 않습니다.

## 저장·삭제

- 기본 저장 위치: 프로젝트의 `data/`. `POSTSCOPE_DATA_DIR` 또는 `--data-dir`로 변경할 수 있습니다.
- SQLite: 작업공간·정규화 메타데이터·출처·관측 구간·격리 사유·수집 작업·불변 집계 스냅샷·설정. 인증 세션 없음.
- 업로드 임시 복사본: 처리 직후 제거. 미처리 파일은 2시간 후 시작·분석 정리 단계에서 제거합니다. 사용자 원본 파일은 수정하지 않습니다.
- 보존 기간: 마지막 확인 후 기본 90일. 만료 메시지와 오래된 메타데이터는 시작·분석 때 정리합니다. 보존으로 제거한 기록의 관측 범위를 무효화합니다. 과거 집계 보고서는 생성 시점 스냅샷으로 유지합니다.
- 작업공간 삭제: `DELETE` 확인 후 관련 메타데이터·분석·생성 파일까지 함께 제거합니다. 진행 중인 수집은 먼저 종료해야 합니다.
- 최소 데이터 백업: 앱을 정상 종료하고 `data/postscope.sqlite3`와 필요한 경우 `data/reports/`만 사용자가 선택한 위치로 복사합니다. `uploads/`는 백업하지 마세요. 임시 원본 JSON이 남아 있을 수 있습니다. DB에는 메모리 인증 정보가 포함되지 않습니다. 원본 대화 JSON을 백업에 추가할 필요는 없습니다.

## 검증

```bash
uv sync --frozen
uv run playwright install chromium
uv run pytest -q
uv run python tests/benchmark.py 100000
```

기준 계산, DST·분수 시간대, 큰 정수 ID, 중복·수정 병합, 격리, HTML·CSV 안전성, 로컬 요청 보호, 삭제·만료, 불변 스냅샷, 동시 갱신, 재시작·호출 제한·인증 만료와 실제 Chromium 사용자 흐름을 테스트합니다. 브라우저가 설치되지 않으면 브라우저 테스트는 명시적으로 건너뜁니다.

구현 범위와 인수검사 한계는 `docs/VALIDATION.md`, 데스크톱·360px 화면은 `docs/dashboard-desktop.png`, `docs/dashboard-mobile.png`에서 확인할 수 있습니다.

## GitHub Actions와 릴리스

[Deploy website](.github/workflows/pages.yml)가 정적 웹사이트의 일일 데이터 갱신·브라우저 검증·GitHub Pages 배포를 처리합니다. `main` 푸시는 기존 데이터를 배포하고, 예약 실행과 `collect=true` 수동 실행만 데이터를 수집합니다.

[CI and Release](.github/workflows/ci.yml)는 다음을 자동화합니다.

- `main` 푸시·Pull Request·수동 실행: Linux와 Windows에서 잠금 의존성 설치, Chromium 설치, 전체 pytest 실행.
- 두 운영체제의 테스트 통과 후: 배포용 소스 ZIP과 SHA-256 체크섬 생성, Actions의 `PostScope-source` 아티팩트로 업로드.
- `v*` 태그 푸시: 같은 검증을 통과하고 태그가 `pyproject.toml` 버전과 일치할 때 GitHub Release와 다운로드 파일 게시.

첫 릴리스 또는 새 버전은 버전을 맞춘 뒤 다음과 같이 게시합니다.

```bash
git tag v1.0.1
git push origin v1.0.1
```

배포 ZIP은 Python 자체가 포함된 EXE가 아닌 소스 배포본입니다. `.venv`, 실제 분석 데이터, 업로드 파일, 세션·인증 파일을 포함하지 않습니다. 로컬에서 동일한 패키지를 만들려면 `python scripts/package_release.py --output-dir dist --tag v1.0.1`을 실행하세요. 릴리스 게시 단계만 저장소 쓰기 권한을 사용하며, CI에는 실제 Telegram 계정 비밀값이 필요하지 않습니다.

## 구조

```text
postscope/
  adapters/desktop_json.py   스트리밍 파싱·행 격리·중복 병합
  adapters/telegram.py       메모리 로그인·SDK·수정/삭제 이벤트
  services/normalizer.py     ID·시각·작성 주체·자료 유형
  services/collector.py      큐·페이지 저장·재개·계정별 대기
  services/analysis.py       불변 스냅샷·집계·기간 비교
  services/reports.py        HTML·CSV·한글 PNG
  storage.py                SQLite 마이그레이션·정리·트랜잭션
  web.py                    로컬 요청 보호·HTTP 계약
  templates/ static/ assets/ 한국어 화면·로컬 Plotly·글꼴
tests/                      합성 데이터·단위/통합/브라우저 검증
```

Plotly.js는 MIT, Nanum Gothic은 SIL Open Font License를 따릅니다. 글꼴 라이선스는 `postscope/assets/OFL.txt`에 있습니다. 자동 예약 수집·다중 사용자·공개 서비스는 기획안에 따라 후속 범위입니다.

기본 분석 기간은 **2025-08-13부터 최신 기록까지**입니다. 2025-08-12의 대량 게시(6,979건) 다음 날을 기준으로 하며 `public/source.json`의 `analysis_start_date`로 지정합니다. 수집 시작일과는 별개입니다. 웹의 **상세 설정 → 초기 기록 포함**에서 이전 기록도 분석할 수 있습니다.

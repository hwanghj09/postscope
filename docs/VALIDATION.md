# PostScope 구현 및 검증 기록

검증일: 2026-11-02. 실제 Telegram 데이터가 없는 환경에서 합성 데이터만 사용했습니다.

## 구현 범위

| 기획안 | 구현 |
| --- | --- |
| FR-01·02 JSON 가져오기 | 단일 `messages`, `chats.list`, 대화 배열 지원. 전체 구조 검사, 선택한 방만 스트리밍 처리, 100 MiB 제한, 행별 격리, 같은 파일·메시지 중복 방지 |
| FR-03 계정 연결 | Telethon 1.42.0, 코드·2FA, 메모리 세션, 연결 해제 및 원격 해제 결과 구분 |
| FR-04 수집·복구 | 일반 이력 페이지 조회, 표본 점검 선행, 계정별 worker 하나, 원자적 페이지·커서 저장, 마지막 페이지 재조회, pause/resume/cancel |
| FR-05 수집 품질 | 서비스 제외·중복·격리·시간 충돌·식별률·앨범 지원·관측 구간·소스 해시 표시/보고서 포함 |
| FR-06~08 필터·통계·앨범 | 적용형 필터, UTC 저장, IANA 시간대, DST, 날짜·요일·시간·히트맵, 확인된 분모, 유형·PDF MIME, 앨범 선형성/경계 처리 |
| FR-09 간격·연속 묶음 | 중앙값·백분위·최소·최대, 공백 제외, 1~60분 기준, 묶음 크기·길이 분포 |

| FR-12 수동 갱신 | 새 작업으로 기간 재조회·기본 키 병합. 최근 7일 겹침을 UI에서 안내. 연결 중 관측한 수정·확실한 채널 삭제 반영 |
| FR-13 보존·삭제·설정 | 마지막 관측 후 90일 기본값, 만료 정리·분모 무효화, 작업공간 cascade 및 파일 삭제, 메모리 세션 제거 |
| FR-14·15 | 기획안대로 자동 예약 수집·다중 사용자·공개 서비스 제외 |

## 자동 검증

`uv run pytest -q`: **48 passed**, 28.02초. 단위·HTTP 통합·Chromium 사용자 흐름, 기준 수치·경계·복구·요청 크기 제한과 릴리스 패키징을 포함합니다. 의존성 Starlette/AnyIO의 비차단 deprecation warning 1개가 있습니다.

- 기준 데이터: 한국 시각 11월 2일 메시지 **3건**, 게시 묶음 **2개**, 문서 **2건 / 1묶음**, 간격 **30·43,170초**, 중앙값 **21,600초**.
- DST 23·25시간 날짜와 반복 시각, Kathmandu의 45분 오프셋.
- 실제 ID > 2^53 보존, 같은 이름의 다른 계정·채널 구분, 이름만 있는 작성자 미확인 유지.
- 파일 재가져오기·수정 병합·잘못된 날짜·비객체 행·서비스 제외·미확인 범위·앨범 경계·0/1건.
- API 모의 응답: 원자적 페이지 저장, 커서 유지, 서버 대기 시각 보존, 새 작업에도 계정 대기 적용, 인증 만료 종료, 수집 시점 이후 시간을 관측 완료로 표시하지 않음.
- 동시 수집 중 분석: 읽기 트랜잭션의 리비전·메시지를 고정하고 읽기 종료 후 별도 쓰기 트랜잭션으로 저장.
- HTML 입력 문자열 이스케이프, CSV 수식 접두어 방어, 비밀값 미반사, 기본 가명 내보내기, 명시적 ID 포함.
- Host·실행 쿠키·CSRF 토큰·Origin 검증. 보고서 임의 경로 접근 차단.
- 작업공간 삭제 후 관계 데이터·보고서 파일 제거, 만료·보존 정리로 캐시 무효화.
- Chromium: 데모의 실제 차트, 필터 변경 미적용, 기록 페이지 이동, 비교, JSON 가져오기→분석→HTML 다운로드.
- 오프라인 HTML: 다운로드한 파일의 **동일한 바이트**를 브라우저 오프라인 상태에서 렌더링. 4개 차트가 외부 HTTP 요청 없이 표시됨. 이 실행 환경의 브라우저 정책이 `file://` 이동을 차단하여 실제 파일 URL 탐색 대신 `about:blank`에 원본 HTML을 주입해 검증했습니다. 일반 PC에서 파일 더블클릭 동작은 별도 확인 대상입니다.
- 360px 화면에서 가로 페이지 넘침 없음. 히트맵은 자체 스크롤·표·방향키 이동 제공.

## v1.0.1 UX 변경 검증

- `uv run pytest -q`: **53 passed**, 88.97초. Chromium 사용자 흐름을 포함하며 의존성 deprecation warning 1개가 있습니다.
- 기본 화면의 슬로건·중복 안내를 제거하고 상세 필터·추가 차트를 접어 배치했습니다.
- 최근 7일·30일은 선택한 대화의 마지막 기록 기준입니다. 초기화는 선택한 대화를 유지하며 기간·작성자·유형 조건을 초기화합니다.
- 가져오기 창 열기·취소에는 작업공간을 만들지 않습니다. 실제 가져오기를 확정할 때 생성합니다. 잘못된 파일과 입력 오류는 대화상자 안에 표시합니다.
- 분석 요청 중에도 화면을 조작할 수 있으며, 다른 작업공간으로 전환한 뒤 도착한 이전 응답은 결과를 변경하지 않습니다.
- 히트맵 표의 건수·시간당 단위, 다운로드 버튼 복원, 모바일 배경 클릭·Escape 닫기를 실제 Chromium 테스트로 확인합니다.
- 통계 계산과 수집 정책은 변경하지 않았으며, 앱·HTTP 버전은 1.0.1로 일치시켰습니다.

## GitHub Actions 준비

- `.github/workflows/ci.yml`: main 푸시·PR·수동 실행 및 버전 태그 지원.
- Linux·Windows에서 전체 테스트 후 소스 ZIP·SHA-256 아티팩트 생성. 버전과 일치하는 태그는 GitHub Release를 게시합니다.
- 외부 Action은 확인된 커밋 SHA, uv는 0.12.23으로 고정했습니다. 기본 권한은 contents:read이며 릴리스 job만 contents:write입니다.
- actionlint 1.7.12 정적 검증 통과. 패키지에서 데이터·세션·인증 파일·캐시를 제외하고 ZIP 무결성·체크섬·재현성을 테스트했습니다.
- 실제 GitHub Actions의 원격 실행은 저장소에 푸시한 뒤 확인해야 합니다. 이 기록은 로컬 검증과 원격 실행을 구분합니다.

## 정적 웹 및 일일 데이터 갱신

- `uv run pytest -q`: **58 passed**, 52.74초. 파일 서버만 있는 환경에서 초기 집계 표시·필터·HTML/PNG 다운로드를 검증했습니다.
- 최초 화면은 `snapshot.json`과 정적 자산만 읽으며 Python worker나 `/api/` 네트워크 요청이 없습니다. 추가 필터·내보내기를 선택할 때만 같은 Python 분석 엔진을 브라우저 worker로 실행합니다.
- `.github/workflows/pages.yml`: 매일 UTC 00:05(한국 09:05)에 데이터 갱신 → 마지막 정상 공개 데이터 커밋 → 웹 빌드·검증 → Pages 배포. 코드 푸시는 기존 데이터를 배포합니다.
- 실제 대상은 사용자가 지정한 `https://t.me/yubin_MPGA`이며 기본 범위는 전체 작성자입니다. 합성 데이터 생성·게시 경로를 제거했습니다. 최초 실제 수집 전에는 연결 대기 상태를 표시하며 가짜 통계나 0건 결과를 생성하지 않습니다.
- 공개 데이터의 메시지·작성자·앨범 ID는 도메인별 HMAC으로 가명화합니다. 본문·원본 ID·API 해시·세션을 공개 파일에 포함하지 않는지 검증했습니다.
- 수집 실패 시 공개 데이터 파일을 교체하지 않는 것을 검증했습니다. 웹사이트는 마지막 성공 데이터를 유지합니다.
- 공개 미리보기 URL은 채널 소개 페이지로 이동하여 게시 내역을 제공하지 않았습니다. 실제 이력 수집에는 사용자 계정 세션을 담은 GitHub Secrets가 필요합니다. 실제 수집 전의 필터·PNG 테스트는 데이터가 없음을 이유로 명시적으로 건너뜁니다.

## 인수검사 및 한계

- **실제 계정 로그인·실제 방 수집 미검증.** 사용자의 API ID/Hash·계정·방·실제 JSON이 제공되지 않았습니다. 공식 서비스에서 임의의 전체 기록 확보를 보장하지 않습니다.
- **Windows 실행 스크립트 수동 검증 미실행.** v1.0.0은 [GitHub Actions](https://github.com/hwanghj09/postscope/actions/runs/41426165436)에서 Linux·Windows 각각 48개 테스트를 통과했습니다. 서버·브라우저·보고서 생성은 CI에서 확인했으며 `start.bat`의 직접 실행은 별도 확인 대상입니다.
- 자동 계정 재로그인과 영구 세션 저장을 구현하지 않았습니다. 기획안이 허용한 메모리 세션 경로를 사용하며 재시작 후 원래 계정으로 재연결합니다.
- 방을 특정할 수 없는 비채널 삭제와 앱이 꺼진 동안의 모든 수정·삭제는 추정하지 않습니다. 수동으로 최근 범위를 재조회해도 오래된 삭제를 전부 확인할 수 없습니다.
- 수집 상태는 성공한 접근 가능 스냅샷을 의미합니다. 미래 시간은 관측 구간에 포함하지 않습니다. JSON에서 전체 기간을 확인하지 않으면 평균·게시율을 제한합니다.
- 앨범 경계를 확인할 근거가 없으면 해당 앨범을 묶음 통계에서 제외합니다. 불완전 그룹을 시간 간격으로 추정하여 완성하지 않습니다.
- 정규화 히트맵의 분자는 확인된 조회 구간에 속하는 게시물만 사용합니다. CSV에 원시 관측 건수와 게시율 분자를 따로 담습니다.
- 간격 CSV는 개별 파생 간격을 담지만 대시보드 API에는 집계만 보냅니다. 기록 표는 불변 스냅샷의 페이지 데이터를 반환합니다.
- 종료 중인 JSON 가져오기는 단일 트랜잭션이므로 커밋되지 않은 결과가 남지 않습니다. 프로세스 종료로 중단된 JSON은 원본 파일을 다시 선택합니다. API 수집은 저장 커서에서 재개합니다.
- 백업은 앱 종료 후 `data/postscope.sqlite3`와 선택한 `data/reports/`만 복사하는 방식입니다. `uploads/`는 제외합니다. 복원 마법사는 범위에 포함하지 않았습니다.
